# 拍照選尺碼（foot-size-advisor）

客人腳踩 A4 紙拍一張照片，網頁自動量出腳長腳寬，給出這雙鞋的尺碼建議。
純靜態網頁，部署在 GitHub Pages，照片只在客人手機上處理，不會上傳。

## 網址用法

```
https://<GitHub 帳號>.github.io/foot-size-advisor/?sku=11802053&back=https://www.dk-shoes.com.tw/SalePage/Index/11802053
```

| 參數 | 說明 |
|------|------|
| `sku` | 對應 `data/sizes/<sku>.json` 的尺碼表，目前用 91APP 銷售頁編號。沒帶或編號錯誤時，結果頁會列出 `data/sizes/index.json` 裡每個商品的建議尺碼與商品連結 |
| `back` | 結果頁「回商品頁」按鈕的網址，沒帶就不顯示按鈕 |
| `debug=1` | 顯示偵測過程的遮罩與數值，調參數用 |

## 客人看到的流程

1. **尺碼對照表**：一打開就是這雙鞋的尺碼表（尺碼、適合腳長、適合腳寬），下面兩個選擇：「不知道，拍照幫我量」或「知道，直接輸入」。
2. **拍照引導卡片**（選拍照才會出現）：紙放深色地板 → 紙貼牆、腳跟貼牆 → 手機在腳尖上方拍。一張卡片只做一件事。
3. **自動量測**：拍完直接算，不需要拖點修正。
4. **照片有問題就引導重拍**：地板太白、紙角沒入鏡、紙被擋住、找不到腳、數字不合理時只能重拍或改用輸入；腳跟沒貼齊、腳太靠邊、腳尖碰紙邊這類輕微問題可以選「仍然看結果」。
5. **結果**：建議尺碼、原因、量測縮圖（紅色是量到的腳、橘線腳尖、綠線腳掌最寬處，看起來不對就重拍）、尺碼表標出建議的那列。可以再量另一隻腳，兩腳取大的。

所有畫面的主要按鈕都固定在螢幕底部，手機瀏覽器畫面再小也看得到。

## 新增商品

在 `data/sizes/` 新增 `<sku>.json`，並把 sku 加進 `data/sizes/index.json` 的 `products`（沒指定商品時的推薦清單）：

```json
{
  "sku": "11802053",
  "name": "商品名稱",
  "verified": true,
  "width_rule": { "enabled": false, "margin_mm": 0 },
  "sizes": [
    { "label": "23號", "foot_min": 225, "foot_max": 235, "shoe_length": 245, "shoe_width": 98 }
  ]
}
```

- 單位一律 mm。`foot_min` 含、`foot_max` 不含。
- `shoe_length`、`shoe_width` 可省略，省略時結果表不顯示這兩欄。
- `width_rule.enabled` 為 `true` 時，腳寬 ≥ 該號鞋寬 + `margin_mm` 就建議大一號，需要每個尺碼都有 `shoe_width`。
- 腳長離該號上限 3 mm 以內，會同時列出大一號。**不會建議小一號**：量測有幾公釐誤差，小一號容易穿不下（實測腳長 27.7 cm 穿 28 號已經剛好貼合）。
- 腳長超過最大號的範圍，直接說這款沒有適合的尺碼；略小於最小號則仍建議最小號。

## 尺碼對照表圖片

商品頁要放的尺碼對照表圖，直接從 `data/sizes/<sku>.json` 產生，跟工具用同一份資料：

```bash
python tools/make_size_chart.py 11802053
```

輸出在 `size-chart/`，寬 1000px。尺碼表改了就重新產生一次。

## 測試

本機開伺服器（ES module 不能用 `file://` 開）：

```bash
python -m http.server 8765
```

- `http://localhost:8765/test/run.html`：自動測試。幾何計算、尺碼判斷，以及 13 種模擬照片（傾斜、橫拍、腳跟在上、暖光、深色襪、白地板、紙角被切等）跑完整流程。
- `http://localhost:8765/test/photos.html`：實拍照片準確度。選多張照片，檔名帶真值（例如 `245x98_赤腳.jpg`），會算出自動抓紙成功率、腳長腳寬誤差，以及建議的修正值。
- `http://localhost:8765/test/debug.html?file=photos/xxx.jpg`：單張照片逐步除錯，印出候選紙角、遮罩、標記點；加 `&corners=x,y,x,y,x,y,x,y` 可用指定的紙角跑後半段。

模擬照片的量測誤差都在 1 mm 內。目前只用兩張辦公室實拍（米色地毯、腿在紙上方、側光有影子）驗過：紙都能自動抓到，腳長和照片上的像素估算一致（22.3 cm / 27.7 cm），腳寬受影子影響較大（修正後 8.9 cm / 10.5 cm），**還沒有用尺量過的真值**，上線前一定要多拍幾張用 `photos.html` 驗收。

## 調參數

所有門檻集中在 `js/config.js`，常用的：

| 參數 | 用途 |
|------|------|
| `LENGTH_OFFSET_MM`、`WIDTH_OFFSET_MM` | 系統性誤差修正，照 `photos.html` 的建議值調 |
| `SEG_DARK_T`、`SEG_CHROMA_T` | 腳和紙的分割門檻，腳抓不完整或把影子當腳時調整 |
| `PAPER_ASPECT_TOL_AUTO` | 自動抓紙的長寬比容許範圍 |
| `BOUNDARY_MM` | 離尺碼邊界多近時同時列兩個尺碼 |

## 原理

1. 縮圖後算「紙張分數」：min(R,G,B) 扣掉 2 倍的色彩範圍（有顏色的地毯、木地板、皮膚都會被壓低，白紙在影子裡仍然沒顏色），再排除有紋理的區域。找最像四邊形的高分區塊，用凸包四條最外側的支撐邊延長相交求四角（角被腿或影子遮住時，看得到的邊延長就能還原），最後回原圖沿四條邊找明暗交界擬合直線，交點就是紙角。
2. 用四個角做透視校正，把紙拉正成 210 × 297 mm，斜拍的變形一起消掉。
3. 在校正圖上，比紙暗很多（深色襪子）或顏色偏離紙張（皮膚）的區域視為腳，紙的明暗漸層用二次曲面擬合吸收。影子只是變暗的紙，不算腳；但深影常帶地板反射的暖色，所以越暗的地方要求越大的色差才算皮膚。
4. 腳跟切齊紙邊時，腳跟點在紙的下緣；腳尖點是沿腳軸最遠的點；腳寬在腳跟算起 55%~80% 的腳掌區段，沿垂直腳軸方向量。腳斜放也能量。

影像處理全部自己寫在 `js/cv.js`、`js/geometry.js`，沒有用 OpenCV.js，整個網站不到 100 KB，LINE 內建瀏覽器用 4G 也能馬上打開。

## 已知限制

- **分不出 A4 和 B5**：A 系列和 B 系列紙張長寬比相同，程式無法用比例分辨。客人用 B5 會量大約 15%，通常會落到「沒有適合尺碼」或被合理性檢查擋下。
- 白色地板、白襪會抓不到紙或腳，已有引導提示。
- 腳有厚度，手機沒在腳尖正上方時腳長會偏差幾 mm。
- 側光打出緊貼腳邊的深影時，腳寬可能量大；膚色很深又在影子裡時，腳的暗側可能被漏掉而量小。確認畫面會把程式判斷的腳畫成紅色，客人要看一眼。
- LINE 內建瀏覽器常擋即時相機，所以用系統相機拍照後上傳，無法在拍照畫面疊引導框。

## 檔案結構

```
index.html            畫面（引導卡片、確認、結果）
css/style.css
js/app.js             流程控制

js/config.js          所有門檻值
js/cv.js              影像基本運算
js/geometry.js        單應矩陣、凸包、直線擬合、長寬比估計
js/paper.js           A4 偵測（紙張分數、支撐邊四角）、紙角精修與合理性檢查、透視校正
js/foot.js            腳部分割、腳跟方向判斷
js/measure.js         自動標記點、腳長腳寬計算
js/pipeline.js        照片 + 紙角 → 量測結果
js/sizing.js          尺碼表載入與建議
js/image.js           讀照片、畫布轉換
data/sizes/*.json     各商品尺碼表（index.json 是商品清單）
tools/make_size_chart.py  依尺碼表產生商品頁用的尺碼對照表圖片
size-chart/           產生出來的尺碼對照表圖片
test/run.html         自動測試
test/photos.html      實拍準確度測試
test/debug.html       單張照片逐步除錯
開發計畫.md            原始規格與實作變更紀錄
```
